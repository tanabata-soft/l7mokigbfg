# モニター募集 ― 申し込みフォーム／使用後アンケート

モニター調査の設計と、フォーム項目の正本。方針の正本は `docs/SERVICE-GUIDE.md`、依頼書は `docs/ORDER-FORM.md`（モニターでも権利条件は通常と同じに適用する）。

## 設計（叩き台）

- 目的: 受付から納品までの流れの検証、仕上がり（ジャケット・音の整え・同期歌詞）の評価、通常価格への納得感、紹介意向の確認
- 募集枠の案: 3〜5組（カバーの記念品も対象に含める）
- **今回の対象はデジタルシングルのみ**（2026-11-12 オーナー決定）: 当初はアルバムを選択肢に残して「※対象外・サービス予定」としたが、同日、オーナー指示で選択肢から外し、選べない形にした。アルバムがサービス予定であることは、質問の説明文で伝える
- **シングルは最大3曲（3曲目はボーナストラック）を公式仕様化**（2026-11-12 オーナー決定）: `docs/SINGLE.md` の「全2曲・固定」を変更し、PRODUCTION／SERVICE-GUIDE／ORDER-FORM と申し込みフォームの選択肢へ反映済み。根拠は NK-S005・NK-S006 のボーナス込み3曲の制作実績。インストゥルメンタル（カラオケ）もボーナストラックとして可（2026-11-12 追加決定）
- 価格: **無料**（2026-11-12 オーナー判断。当初のモニター価格案から変更。アンケートの価格質問は「通常価格なら払うか」の検証として残す）
- モニターの条件: ①納品後のアンケート回答（必須） ②不具合や気づきを率直に教えてもらう ③実績紹介への掲載は任意（可否はアンケートで確認）
- フォームの置き場所: **Google フォーム ×2 で作成・公開済み**（2026-11-12、Google フォーム接続経由で Muse が作成）。回答は本人の Google アカウント側に貯まる
  - 申し込み: https://docs.google.com/forms/d/e/1FAIpQLSd7FK5byLhfhlmKQpxzSUYSsmKPexn0DiCKeuFcMuQztbKT3g/viewform
  - アンケート: https://docs.google.com/forms/d/e/1FAIpQLSeZnxNwmwPqUtFrjqW8E6u46FtDKtBLFkEM1K3q5w1gLr5wtw/viewform
- **申し込みはココナラとは別建て**（2026-11-12 オーナー指示）: 募集の告知と申し込みはココナラを経由しない。ココナラで接点を持った相手を外部へ誘導する形にはしない（ココナラの規約に触れるため、モニター募集の告知はココナラの外で行う）。モニターは無料なので、課金の受け取り自体が発生しない
- **ココナラで受注した場合の進め方**（2026-11-12 公式ルールで確認）: 受注後も Google フォームへは誘導しない。ココナラの禁止行為に「他サイトの登録フォームへ誘導し会員登録、または個人情報を登録させる行為」が明示されているため。ヒアリングは依頼書の項目をトークルームの文面で聞き、素材はトークルームの添付で受ける（1回の送信で5ファイル・合計200MBまで。音声 mp3／wav、動画 mp4／mov、画像、zip 可）。200MB を超える場合は圧縮・分割し、それでも無理な場合のみ、公式ヘルプが許容しているギガファイル便（ダウンロード専用）の URL をトークルームで共有する。Google フォームはココナラ外の経路（モニター・直接の申し込み）専用にする
- **受付メールの Apps Script 方式は不採用**（2026-11-12 実測）: 承認の段で高度な保護機能プログラムによりブロック（エラー 400: policy_enforced）。**受付確認はフォーム標準の「回答のコピーを常に送信」で行う**（2026-11-12 オーナー決定）。前提として設定側の「メールアドレスを収集する」をオンにする必要があり、オンにしたら重複する既存のメールアドレス質問は Muse が API で削除する。経緯とコードは `docs/MONITOR-AUTOREPLY.md` に保存
- **フォームの置き場所は Google フォームで確定**（2026-11-12 オーナー決定）: 理由は無料運用。Vercel の無料枠は非商用のみで事業には使えず、有料化すると売上前から固定費が出る。Google フォームは無料で、保存先も契約中の Google ドライブ（5TB）が使える
- **フォームの WEB サービス化**（保留）: 自前の WEB サービスとして公開する案は Vercel で進めたが、プロジェクト操作に必要な「チームアクセス」承認を Muse 側の道具から発行できず保留。サービス一式（募集ページ＋フォーム＋保存処理）は `~/workspace/monitor-service/site/` に作成済みで、権限が解ければそのまま載せられる。再検討は「売上が立ち、窓口の自動化に月額を払う価値が出てきたら」

## フォーム 1: 申し込みフォーム

タイトル案: デジタルCD制作 モニター申し込み
冒頭文案: 「曲はできた。でも“作品”になっていない」人のための仕上げ専門サービスのモニター募集です。無料で制作し、納品後にアンケート（5分程度）への回答をお願いしています。曲はお客様が作ったものをお持ち込みいただきます（作曲・生成の代行はしていません）。

| # | 質問 | 形式 | 必須 |
|---|---|---|---|
| 1 | お名前（活動名・屋号でも可） | 短文 | ○ |
| 2 | （メールアドレスはフォーム設定の「メールアドレスを収集する」で収集。質問としては置かない。2026-11-12 に質問版を削除済み） | ― | ― |
| 3 | 希望する形態 | 選択: デジタルシングルCD（最大3曲）のみ（アルバムは選択肢から外し、説明文で「サービス予定」と伝える。「まだ決まっていない」も置かない） | ○ |
| 4 | 曲の種類 | 選択（複数可）: 自作曲（録音・打ち込み）／自分で生成した AI 曲／自分たちの演奏のカバー（記念品）。「まだ曲がない」は置かない（曲がなければサービスが成立しないため。2026-11-12 オーナー判断） | ○ |
| 5 | （削除済み）曲のファイルについて ― アップロード欄と「曲の種類」で代替できるため削除 | ― | ― |
| 6 | 作りたいもの・用途（例: 学祭バンドの記念、自分の曲の作品化） | 長文 |  |
| 7 | 希望納期 | 短文 |  |
| 8 | 権利について確認しました | チェック: 「曲は自分の自作曲・自分で生成した AI 曲・自分たちの演奏のカバーのいずれかで、市販音源や他人の曲・演奏ではありません。カバーの場合は販売・一般公開をしません」 | ○ |
| 9 | モニター条件に同意します | チェック: 「納品後のアンケートに回答します」 | ○ |
| 10 | その他・質問など | 長文 |  |

データの登録（2026-11-12 最終決定）: **申し込みは1本のフォームで完結させる**（別フォームは作らない。オーナー決定）。曲とジャケットのデータは、フォーム内の「ファイルアップロード」質問で直接受け取る。アップロード質問を入れると回答者全員に Google サインインが必須になるが、それを許容する（同決定）。
- アップロード質問は Google フォームの API では作成・変更ともできない仕様（実測でエラー確認済み）のため、オーナーが編集画面から手動で作成した（2026-11-12 完了）。**最終形は曲ごとの枠**（1枠に集約する案から変更。ファイル名での判別が不要になり、どの曲のファイルか確定する）: 「表題曲のファイル」「カップリング曲のファイル」「ボーナストラックのファイル」の3枠＋「ジャケットデータ（画像ファイル）」。設定: 曲の3枠は各 最大5ファイル・1ファイル 1GB（説明文では「音源＋歌詞の2ファイルまで」と案内）、ジャケットは 最大5ファイル・1ファイル 100MB（説明文では「4枚まで」と案内。最大数の選択肢に 4 がないため設定は 5 のまま）。形式制限なし（ANY）。「表題曲のファイル」のみ必須（最低1曲がないと申し込めない形。2026-11-12 オーナー設定を確認済み）で、他は任意。1GB の理由: FHD 動画は1曲で数百MB になるため。**注意（実測で発生）**: アップロード枠の「最大数×最大サイズ」の合計がフォーム全体の上限を超えると、回答の受け付けが自動で停止する。最終形の合計は約15.5GB のため、フォーム全体の上限は 100GB に引き上げ済み（変更は警告文の「変更」リンクから）
- 共有リンクの欄は置かない（2026-11-12 オーナー決定で削除）: 受け取りはフォーム内のアップロードに一本化する。フォームは最終的に全12項目（うちアップロード4質問＝曲ごと3枠＋ジャケット。「曲のファイルについて」は、アップロード欄と「曲の種類」で代替できるため削除）

運用: 申し込みが来たら、通常の依頼書（`docs/ORDER-FORM.md`）で素材と権利確認を受けてから制作に入る。このフォームは入口の登録用で、依頼書の代わりにはしない。

## Google フォームでの作り方（オーナー作業）

1. Google フォームで新規作成し、このファイルの表どおりに質問を写す（形式と必須も表のとおり）
2. 申し込みフォームは、回答先をスプレッドシートに連携しておく
3. フォームの URL を募集の告知に貼る。アンケートの URL は納品時にだけ渡す
4. 個人情報（名前・メール）は連絡目的だけに使い、第三者に渡さない。不要になった回答は削除する
