# START HERE（新作を作る人・AI へ）

このリポジトリは、デジタルCDシリーズの**エンジン（テンプレート）の正本**です。新作（アルバム／シングル）は、直近の作品のリポジトリではなく、**この repo をコピーして**作ります。

仕組みは「エンジン」と「データ」の分離です。エンジン（`src/` のうち `src/album/` 以外など）には触らず、`src/album/` の中身を新しい作品の内容に差し替えて作ります。境目の詳細は `docs/PRODUCTION.md` の「エンジンとデータの境目」にあります。

この repo には雛形の作品（シングル形態・2曲・10秒の仮音源）が入っていて、そのまま `npm run verify` / `npm run test:e2e` / `npm run shots` が通ります。新作では雛形データを実在の曲・絵・文章に置き換えます。

制作の引き継ぎ文（シリーズの全体像・分担・守ることを1枚にまとめたもの）は `docs/HANDOVER-BRIEF.md` にあります。初めて引き継ぐ場合は、まずこちらを読んでください。

## この repo の置き場所と公開の役割分担

- この repo は `mmishina-art/digitalcd-engine`（**非公開**）。**公開しません。GitHub Pages も有効化しません。**
- 作品の公開先は、配布用 Organization `tanabata-soft` 配下の**公開**リポジトリ（名前は作品名を含まないランダムな文字列）です。新作ごとに新規作成し、GitHub Pages で公開します。
- テンプレート（非公開・作る場所）と作品（公開・届ける場所）は役割が違います。混同しないこと。

## 読む順番

1. `docs/SINGLE.md` — シングル形態（デジタルシングルCD）の仕様。シングル制作ではこちらが仕様の正本。アルバム制作では読み飛ばしてよい。
2. `docs/PRODUCTION.md` — 制作手順と、末尾の「運用ルール（引き継ぎ用）」。素材の作り方から公開まで。
3. `CLAUDE.md` — アプリの技術方針（PWA 要件・デザイン・テストなどの共通ルール）。
4. `docs/HANDOVER.md` — 引き継ぎメモの書式（雛形）。コピー先の作品 repo で、作品の現在地をここに書き続ける。
5. `docs/` 配下の DESIGN-STUDY — ジャケット様式の判断材料（必要なとき。アルバムは `ALBUM-DESIGN-STUDY.md`、シングルは `SINGLE-DESIGN-STUDY.md`）。
6. `docs/SERVICE-GUIDE.md` — サービスとして受注する場合の顧客向け案内（曲はお客様が作ったものが基本、生成代行はしない）。受注時はこれを正とする。依頼書は `docs/ORDER-FORM.md`。

## 新作の作り方（流れだけ。詳細は PRODUCTION.md）

1. この repo をコピーして、作品用の新しいリポジトリを作る（GitHub は `tanabata-soft` 配下・ランダム名・公開）。
2. `package.json` の `name`（アプリ ID）を新しい ID に、`version` を `1.0.0` にする。カタログ番号を付番する（下記）。
3. `src/album/` を作品の内容に差し替える（素材の作り方は PRODUCTION.md 前半）。
4. アプリ名と色を付け替える（`vite.config.ts` と `index.html` の2か所ルール）。アイコンを表ジャケットから作り直す。
5. `e2e/app.spec.ts` と `scripts/shots.mjs` の期待値を作品の収録内容に合わせる（テンプレート同梱はシングル形態用）。
6. `npm run verify` ＋ `npm run test:e2e` ＋ `npm run shots` を通し、単体 HTML プレビューでオーナーの実機確認を仰ぐ。
7. 公開する（feature ブランチ → PR → CI → squash マージ → Pages。有効化と保護ルールは PRODUCTION.md 手順8）。
8. 作品 repo の `docs/HANDOVER.md` を最新の状態に書き、ダッシュボードにも反映する（運用ルール参照）。

## オーナーとの分担

- 曲の生成はオーナーが自分の Gemini アプリ（AI Pro）で行い、チャットへ MP4 をアップロードして渡します。制作側は、受け取った素材から組み立てます。
- Gemini API で音楽生成はしません（API は音声合成専用というオーナー決定）。
- 確認ポイントは3か所（①組み合わせ・曲順、②表ジャケット候補、③歌詞の漢字の最終確認）ありますが、どれも進行を止める関門ではありません。確認が取れない場合は推奨案で進め、仮置きとして納品報告の仮置きリストに必ず残します。

## 作業場所と採番

- 作業フォルダは作品ごとに `~/workspace/` に作り（例: `single-nksNNN/`）、その中の `repo/` にリポジトリを置きます。
- アプリ ID は作品ごとに新規に付けます（`package.json` の `name`。既存作と重なると保存データやキャッシュが混ざります）。
- カタログ番号は、アルバムが NK-NNN、シングルが NK-SNNN の連番です。使用済みの番号は再利用しません（NK-S005 は私的鑑賞用の例外盤に使用済み。通常ラインのシングルの続きは NK-S006 から）。最新の採番状況は、デジタルCDダッシュボードの台帳で確認します。
